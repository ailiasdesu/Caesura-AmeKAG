## 2. Logic Chain

1. **Windows Packaging Chain**:
   - `CMakeLists.txt` already possesses mature CPack and install definitions. Running `cpack -C Release -G ZIP` produces a valid Windows ZIP containing the executable, DLLs, assets, and shaders.
   - To match the requested filename `CaesuraAmeKAG-1.0.0-rc.1-win64.zip`, we can either set `CPACK_PACKAGE_FILE_NAME` via CMake cache argument (`-DCPACK_PACKAGE_FILE_NAME=CaesuraAmeKAG-1.0.0-rc.1-win64`) or have the distribution packaging script copy/alias the CPack output.
2. **Web Packaging Chain**:
   - `scripts/package_game.sh` packages the web runtime and demo assets into `dist/example_game`.
   - By copying `web/sw.js` and `web/manifest.webmanifest` to the output root and creating a zipped bundle `CaesuraAmeKAG-1.0.0-rc.1-web.zip`, the Web distribution becomes completely self-contained, PWA-enabled, and offline-capable.
3. **Android Packaging Chain**:
   - `scripts/build_android_release.sh` already implements complete APK and AAB compilation, PKCS12 signing, `zipalign`, and `apksigner` verification.
   - The output artifacts from `android/app/build/outputs/` (`app-release.apk` and `app-release.aab`) can be staged and renamed into `artifacts/dist/`.
4. **Unified Distribution Assembly Chain**:
   - A unified Python packaging script (`scripts/package_distribution.py`) will orchestrate:
     - Collection and staging of Windows ZIP, Web ZIP, Android APK, and Android AAB into `artifacts/dist/`.
     - Computation of SHA-256 hashes for all 4 packages, writing standard `artifacts/dist/checksums.txt`.
     - Generation of `artifacts/dist/release-manifest.json` containing complete metadata, target architectures, format details, and verification statuses.
     - Execution of `--verify` mode to validate all checksums cryptographically.

## 3. Caveats

1. **Windows Environment Toolchains**:
   - CPack requires MSVC Release build to have completed (`cmake --build build --config Release`).
   - Android APK/AAB build requires Android SDK Build-Tools and NDK; when running without full physical Android SDK, `--ephemeral-key` or pre-built `.so` staging is utilized as documented in `scripts/build_android_release.sh`.
2. **Web Browser Wasm Offline Host**:
   - `web/vite.config.js` pins `glue.wasm` to `web-assets/glue.wasm` so that Wasmoon does not rely on external CDN (unpkg), ensuring pure offline static hosting.
