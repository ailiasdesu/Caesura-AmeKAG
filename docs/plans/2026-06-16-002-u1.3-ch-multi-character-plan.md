## Problem Frame

The `[ch]` command in `scripts/kag/commands/text.lua` renders character dialogue but has no concept of screen position (left/center/right) or multi-character state tracking. In a galgame engine, multiple characters frequently appear on screen simultaneously — each at a distinct position — and the dialogue system must know which character is speaking to render text at the correct position and track character visibility for save/load and scene transitions.

**Current behavior:**
- `[ch name="Hero" text="Hello!"]` renders speaker name at `(48, 540)` and message at `(48, 580)` — always top-left of message box
- No `ctx.characters` table exists
- Character sprites are managed independently by `[fg]`/`[image]` commands — no linkage between `[ch]` and which sprite is on screen

**Target behavior:**
- `[ch name="Hero" text="Hello!" pos="left"]` renders name+text left-aligned
- `[ch name="Heroine" text="Hi!" pos="right"]` renders name+text right-aligned
- `ctx.characters` tracks `{name, pos, layer, sprite}` for each active character
- Multiple `[ch]` calls for different characters produce state-aware rendering

---

## Scope

**In scope:**
- Add `pos` parameter (`"left"`/`"center"`/`"right"`) to `TextCommands.ch` in `scripts/kag/commands/text.lua`
- Create and maintain `ctx.characters` table — a registry of active on-screen characters
- Positional text rendering: name box and dialogue text offset based on `pos`
- Interaction between `[ch]` and `[fg]`/`[image]`: when a character's sprite layer exists, `[ch]` associates dialogue with that layer

**Out of scope (deferred):**
- C++ `ILayerManager` changes — the Lua `layers.lua` RTT pipeline already supports multiple layers
- Automatic sprite loading from `[ch]` — sprite management stays in `[fg]`/`[image]`
- Expression/emotion variants on `[ch]` — deferred to future iteration
- Save/load persistence of `ctx.characters` — handled by existing `System.saveplace`/`loadplace` which snapshots `ctx`

---

## Key Technical Decisions

**K1: `pos` is a text-positioning concern, not a sprite-positioning concern.**

`[ch]` controls where dialogue text appears. Sprite positioning is controlled by `[fg]`/`[image]`/`[position]` commands. This separation follows the existing architecture where text and layer commands are different modules. When `pos` is specified, `[ch]` also updates `ctx.characters[name].pos` so that subsequent `[ch]` calls for the same character inherit the position.

**Rationale:** Changing `[ch]` to also manage sprites would violate the single-responsibility pattern already established across 68 KAG commands.

**K2: `ctx.characters` is a flat table keyed by character name.**

```lua
ctx.characters = {
    Hero = { pos = "left",  layer = "fg0", sprite = "hero_normal.png" },
    Heroine = { pos = "right", layer = "fg1", sprite = "heroine_smile.png" },
}
```

**Rationale:** Flat table is simple to iterate, serialize, and diff. KAG scripts typically have <5 characters on screen at once, so lookup by name is efficient enough.

**K3: `[ch]` with a new character name auto-registers in `ctx.characters` with default position "center".**

**Rationale:** Backward compatible — existing scripts that don't specify `pos` get centered text, and the character is still tracked for save/load.

## Implementation Units

### U1.3.1: Add `pos` parameter to `TextCommands.ch`

**Files:**
- `scripts/kag/commands/text.lua` — modify `TextCommands.ch`

**Patterns to follow:**
- Existing parameter extraction pattern in `TextCommands.ch`: `params.name or params.character or ""`
- Position calculation: `left → x=48`, `center → x=540` (screen center), `right → x=1032` (1280-wide screen minus ~248px for text)

**Changes:**
1. Extract `pos` parameter: `local pos = params.pos or "center"`
2. Validate: only `"left"`, `"center"`, `"right"` accepted; default to `"center"`
3. Calculate `nameX` and `msgX` based on position:
   - `left`: `nameX = 48`, `msgX = 48`
   - `center`: `nameX = 540`, `msgX = 48` (name centered, text left-aligned for readability)
   - `right`: `nameX = 1032`, `msgX = 1032 - estimated_text_width`
4. Pass calculated positions to `backend.render_text()` calls
5. Update `ctx.characters` table

### U1.3.2: Implement `ctx.characters` registry

**Files:**
- `scripts/kag/commands/text.lua` — modify `TextCommands.ch`

**Changes:**
1. Initialize `ctx.characters = ctx.characters or {}`
2. On each `[ch]` call: `ctx.characters[speaker] = { pos = pos, layer = params.layer, sprite = params.storage }`
3. When `pos` is omitted but character exists in registry, inherit stored position
4. When `layer` parameter is present, store the layer association

### U1.3.3: Tests

**Files:**
- `tests/cpp/test_kag_execution.cpp` — add test cases

**Test scenarios:**
1. `[ch]` with `pos="left"` renders text at left-aligned coordinates
2. `[ch]` with `pos="right"` renders text at right-aligned coordinates
3. `[ch]` without `pos` defaults to center (backward compat)
4. `ctx.characters` is populated after first `[ch]` call for a character
5. Second `[ch]` for same character inherits stored position
6. Invalid `pos` value ("top") falls back to center without crash
7. `ctx.characters` persists through `[p]` (page break) — character state survives dialogue advance

**Test file location:** `tests/cpp/test_kag_execution.cpp`, new SECTION "KAG: ch command multi-character"

## Risks

- **R1: Text truncation at right position.** Right-aligned text with long character names may overflow the 1280px screen. Mitigation: clamp `msgX` to minimum 48px from right edge.
- **R2: Layer integration mismatch.** If `[ch]` references a layer that doesn't exist, behavior is undefined. Mitigation: only store layer association, don't create layers from `[ch]`.
- **R3: Save/load compatibility.** `ctx.characters` is a new field. Mitigation: existing `System.saveplace`/`loadplace` snapshots `ctx` wholesale — no migration needed as long as no existing saves rely on absence of `ctx.characters`.
