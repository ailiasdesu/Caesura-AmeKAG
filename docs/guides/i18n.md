# 多语言本地化（i18n）

> 纯 Lua 本地化管线：`scripts/ks_i18n.lua` 从 `.ks` 场景提取对话并生成
> 翻译模板，`scripts/i18n.lua` 在运行时加载语言表并本地化文本。零 C++
> 依赖，可在命令行 / 编辑器 / CI 独立运行。

## 工作机制

两种本地化机制，都汇聚到 `i18n.localize(text, scene)`，由 KAG 文本管线
（`[ch]`/`[text]`）在标记解析**之前**应用：

1. **逐行翻译**：语言表的 `lines` 表把
   `"<scene>:<fnv1a(原文)>"` 映射到本地化文本（Ren'Py 风格行翻译）。
   键是内容寻址的（把原文跑一次 FNV-1a 得 8 位十六进制哈希），所以场景
   重排或运行时生成的对白不会让翻译错位。
2. **`{key}` 标记展开**：任何文本里的 `{key}` 被 `i18n.t(key)`
   替换。内联标记名（`b`/`i`/`s`/`color`/`size`）被白名单豁免，从不
   当作翻译 token——内联标记优先。

优先级：**逐行翻译 > `{key}` 展开 > 原文原样返回**。

## 生成语言模板

```bash
# 扫描 demo 目录，生成/合并 assets/lang/zh.lua（默认 dir=demo, lang=en）
lua scripts/ks_i18n.lua --dir demo --lang zh

# 合并进已有语言文件（保留已有译文，只追加新键）——推荐增量工作流
lua scripts/ks_i18n.lua --dir demo --lang zh --update

# 未翻译清单（CI 门禁）：双向校验 — 逐行缺译 + {key} 字符串表键缺
lua scripts/ks_i18n.lua --dir demo --lang zh --missing

# {key} 字符串表引用清单（哪些键被场景引用、复用几次、哪些未解析）
lua scripts/ks_i18n.lua --dir demo --lang zh --keys
```

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--dir <dir>` | `demo` | 要扫描的场景目录 |
| `--lang <code>` | `en` | 语言代码，决定输出文件名 |
| `--out <path>` | `assets/lang/<lang>.lua` | 输出/合并目标 |
| `--update` | 关 | 合并进已有文件，保留旧译文，只追加新键 |
| `--missing` | 关 | 双向校验：逐行(`lines`)缺失译文 + `{key}` 字符串表键缺失；|
|            |   | 任一方向有缺失都退出码 1（翻译完整性门禁） |
| `--keys` | 关 | 打印 `{key}` 字符串表键引用清单（含复用次数/场景/首现文案）；|
|          |   | 有未解析的引用键时退出码 1 |

退出码：`--missing` / `--keys` 只要有尚未翻译的键或未解析的 `{key}` 引用
就返回 `1`（翻译完整性门禁）。

## 运行时本地化

```lua
local i18n = require("i18n")

i18n.current          -- 当前语言代码（默认 "zh"）
i18n.load("ja")       -- 加载 assets/lang/ja.lua（comments+return 工具生成格式）
i18n.t("greeting")    -- 查 {key} 字符串，回退英文，再无则原样返回
i18n.expand("{greeting} world")   -- 展开 {key} 标记（内联标记豁免）
i18n.localize("原文", "scene.ks") -- 逐行翻译 > {key} 展开 > 原文
i18n.available()      -- 扫描 assets/lang/ 可得语言列表

-- 运行时字典选择与模板插值（P1 运行时 API）
i18n.set_language("ja")          -- 切换字典：当前语言 -> default_language -> 原文键
i18n.current_language()          -- 当前语言代码
i18n.default_language            -- 回退字典语言（缺省 "en"，可配置）
i18n.translate("Hello, {name}!", { name = "Caesura" })  -- {占位符} 插值
i18n.reload("ja")                -- 热重载语言文件（编辑后免重启）
```

语言文件支持两种写法：手工 `{...}` 裸表字面量，或工具生成的
`-- 注释 + return {...}` 形式（`load` 两种都接受）。

## 端到端示例

```bash
# 1) 提取场景对话，生成空模板
lua scripts/ks_i18n.lua --dir demo --lang zh
#   -> assets/lang/zh.lua，lines 表每行一个 "<scene>:<hash>" 空占位

# 2) 译者填好译文（或直接复用 --update 保留已填部分）

# 3) 检查还有多少没翻译（CI 门禁：全翻完退出码 0 才放行）
lua scripts/ks_i18n.lua --dir demo --lang zh --missing

# 4) 运行时引擎按当前语言加载并本地化对白
```

键与原文在模板里以注释随行呈现（`-- original: ...`），供译者对照；
`--update` 重建模板时保留已有译文与顶层设置键，绝不丢弃手工字符串。

## 翻译工作流（提取 → 翻译 → 回填 → 验证）

`ks_i18n.lua` 把整条链路闭环，四个命令链覆盖 提取→翻译→回填→验证：

```bash
# ① 提取 extract：扫描场景，生成/合并逐行模板（--update 增量保留旧译文）
lua scripts/ks_i18n.lua --dir demo --lang zh --update

# ② 查看 {key} 字符串表引用清单（翻译记忆：引用哪些键、复用几次、
#    首现文案作上下文；未解析键标 <<MISSING>>，退出码 1）
lua scripts/ks_i18n.lua --dir demo --lang zh --keys

# ③ 译者填好译文（编辑 assets/lang/zh.lua：顶层字符串键 + lines 逐行）

# ④ 回填校验 backfill：双向核对——逐行译文 + {key} 字符串表键都齐全才放行
lua scripts/ks_i18n.lua --dir demo --lang zh --missing && echo complete

# ⑤ 运行：引擎按当前语言加载字典并本地化对白（[i18n language=] 热切换）
```

**验证命令**以退出码充当 CI 门禁：`--missing` 任一方向（逐行空占位、未解析
`{key}` 引用）有缺口即返回 `1`；`--keys` 有未解析引用键即返回 `1`。全绿（退出
码 0）才代表 场景引用的键都在词典里 ——这正是回填校验的意义。

### 提取：{key} 引用收集

纯文本（`[ch]`/`[text]`/`[button]`/`[sel]` 的 text 参数 + 裸文本 token）里的
`{key}` 会被 `ks.extract_key_refs`/`collect_key_refs` 收集成**带上下文的清单**：
每个键带首现文案、被多少个**场景**引用（复用计数）、以及所在 `.ks` 文件名。
内联标记（`{b}`/`{i}`/`{s}`/`{color}`/`{size}`）与运行时 `${expr}` 插值被豁免，
不会误当键。一个键被多处引用的 一处翻译、全局复用 就是引擎自带的
翻译记忆（v1 简化版）；`--keys` 的复用计数提示译者哪些键译一次效益最高。

### 回填：键完整性校验

`ks.find_key_missing(dir, langData)` 返回所有 **场景引用但词典缺失** 的 `{key}`：
langData 顶层键即字符串表（`lines`/`_version` 等结构字段除外）。`--missing` 把
它与逐行 `lines` 缺译合并成一份报告，缺一即门禁失败。

### 复数键在流程里的位置

复数变体表是字符串表的一个**顶层键值**（值是 `{ one=..., other=... }`）。提取时
它作为 `{items}` 引用被收集；回填时只要该顶层键存在（值是表）即视为已解析、
不报缺；运行时须用 `i18n.translate("items", { n = <count> })` 在 `[iscript]`/
`[emb]` 里算好数量再插值（裸 `{key}` 走 `[ch]` 会落通用 `other` 形且残留 `{n}`，
见下方 ⚠️）。

## 复数与数字格式（G9）

字符串表的**值**除了普通字符串，还可以是复数变体表，配合
`i18n.translate(template, { n = <数量> })` 做按数量的复数与数字插值：

```lua
-- assets/lang/en.lua（顶层键）
items = { one = "{n} item", other = "{n} items" },
```

运行时按当前语言的复数规则选择变体，再插值 `{n}`：

```lua
i18n.translate("items", { n = 1 })  -- en: "1 item"    （one）
i18n.translate("items", { n = 3 })  -- en: "3 items"   （other）
```

- **en**：数量 1 → `one`，其余 → `other`（CLDR 风格类别）。
- **zh / ja**（无单复数区分）：永远用单形（`other`），即使条目带了
  `one` 也按 `other` 解析，保证两种语言只需维护一个不变式。
- **缺失变体回退**：命中类别缺失时回退 `other` 再 `one`，再没有则空串。
- **无数量参数**：`t()` / `expand()` / 不带 `{n}` 的 `translate()`
  都解析到通用（`other`）形式，绝不泄漏 raw-table 句柄。
- **⚠️ 复数键不要用裸 `{key}` 走 `[ch]`/`[text]`/`[button]` 管线**：这些命令
  经 `i18n.localize` → `expand` → `t()` 展开，**没有 `{n}` 数量输入**，所以
  复数表键会解析成通用 `other` 形式并把 `{n}` 原样残留（round 110 回归案例：
  `[ch text="共 {items}"]` 渲染成 `共 {n} items`）。复数键必须在
  `[iscript]`/`[emb]` 里先算好数量，再用 `i18n.translate(key, { n = <count> })`
  把结果字符串喂回文本；引擎会在裸 `{key}` 命中复数表键时打印一条
  `[i18n] WARN` 提示改用 `translate()`。
- 变体里用 `{n}` 占位符（与第 75 轮一致），数量会插值为字面数字。
- **模板往返安全**：`ks_i18n.lua --update` 会用 `serialize_field`
  把带嵌套表的复数条目序列化保留，不会在合并时丢弃变体。
